曲线坐标提取器（digitizer_app）— 使用说明 / 最终版
================================================================

一、运行环境
  · MATLAB R2023b 或更新（prctile 需为内置）
  · Image Processing Toolbox（bwdist / bwmorph / imerode / imclose / bwlabel / regionprops 等）

二、启动（不用先 cd，程序自己定位文件夹）
     app                % 一键：自检 -> 提取全部 7 张图 -> 打开界面
     verify_all         % 一键全量验证，报告 qa/VERIFY_report.txt
     digitizer_app      % 只开界面
     run_all            % 只做批处理提取
     check_kinks        % ★严格判据：逐条曲线找"折角"（跳线/粘连的直接证据）
     check_bias2        % ★严格判据：逐列画"曲线行 - 墨心行"偏差曲线
     t_profile          % 逐条曲线画抖动曲线
     qa_line            % 重合度指标 + 漏检诊断图
     audit_curves       % 失真体检（抖动/被大点吸附/出墨/撞车）
     check_calib        % 用 x=0、y=0 虚线独立校验坐标标定

三、这一轮把判据收紧了 —— 之前的指标太宽，看不出你指的问题
  原来的 cover（"笔画有没有被认领"）对 fig3B/3C/3E 早就报 1.0000，但你看到的问题是真的。
  于是新增两条严格判据：
    · kink  = |二阶差分| 的 p90 / max  —— 折角。跳线、粘连、沿着圆环走都会留下折角。
    · bias  = 曲线行 − 该列墨迹亚像素中心 —— 压得正不正，逐列画出来看走势。
  用这两条一量，问题立刻现形：fig3D 有 5 条曲线的折角 p90 高达 8~16 px，
  fig3E 蓝线有 166 处折角（最大 12 px）。

四、找到的两个真正根因（都不是"参数没调好"）
  ★ 根因 1：亚像素窗口顺着"同色且相连的竖直结构"无限外扩
      fig3E 的数据圆点画在曲线**下方**，靠误差棒的竖杆与曲线连成一体、颜色完全相同。
      原来的亚像素窗口从曲线行出发"只要还是本线颜色就继续扩"，于是一路扩进圆点，
      加权重心被拽下去，曲线在该处下陷 12 px 再弹回 —— 这就是你说的
      "把数据点圆的周长识别成了曲线"。
      修法：窗口夹到 ±2.5 倍线宽（既罩得住 fig2E 那种 18 px 的粗线，又够不到远处的圆点）。
      效果：fig3E 折角 166 处 -> **0 处**，最大折角 11.98 px -> **0.23 px**。

  ★ 根因 2：一阶斜率惩罚管不住"缓慢来回跳"
      fig3D 密集带里，DP 会以约 20 列为周期在相邻两条线之间来回 —— 每列只差 1~2 px，
      一阶惩罚 λ·Δ² 几乎不惩罚，所以加大 λ 也没用（λ 加到 0.25 覆盖率反而崩到 0.94）。
      这是**曲率**问题，必须用二阶惩罚。
      修法：fig3D 启用 snake_smooth（二阶差分惩罚），并把 λ 调到 0.08。
      效果：折角 p90 从 7.1 px 降到 **0.14 px**，10 条曲线里 >1px 的折角 **0 处**，
      而覆盖率只从 0.9988 掉到 0.9983。

  顺带验证：把 snake 的目标从 0.30 收紧到 0.15 / 0.06，折角反而**变多**
  （0.30 -> 0.15 时 fig3B 折角 32 -> 458）。原因是目标太紧时 λ 被迫变小，
  曲线开始跟着测量噪声走。所以 0.30 就是最优点，不是没调到位。

  · cover  = 曲线笔画被认领的比例（按长度加权），越接近 1 越好
  · 折角   = |二阶差分|；这是"曲线是否连续光滑"的硬指标
  · bias   = 曲线行与该列墨迹亚像素中心之差；fig3A/3D 的极少数大值出现在
             x≈0 的合并带（那里多根线共用一个墨峰，度量本身无意义）

  坐标精度独立校验（check_calib，用图里 x=0 / y=0 虚线反推）：
    fig2E 误差 0.158% 量程 | fig3A 0.145% | fig3F 0.167% —— 约半个像素。

六、引擎 curve_extract.m 的七个阶段
    ① 墨迹掩膜   亮度/色度阈值；去长轴脊；去刻度线；去图例文字；可选 inkMax
    ② 颜色候选   腐蚀取核心像素 -> k-means -> 按"能在多少不同列上成为最优匹配"打分
    ③ 逐候选 DP  混色似然 + 竞争项 + 厚度惩罚；抛物线下包络求解，不限步长；
                 亚像素窗口用"本线似然"界定并**夹到 ±2.5 倍线宽**
    ④ 最大覆盖选路  贪心覆盖最多未认领墨迹，并禁止与已选路径撞车
    ⑤ 漏检回收   仍有成片墨迹没人认领 -> 取其颜色再求路径 -> 重新选路，循环迭代
    ⑥ 颜色重吸附 snap_to_color  逐列回到本颜色的墨峰（fig3F 用它跟随尖峰）
    ⑦ 光滑先验   snake_smooth   一维主动轮廓（二阶惩罚 + Tukey 粗差抑制 +
                 厚度置信度）；强度按图分别设定

七、逐图参数（extract_opts.m：界面与批处理共用同一套，不会跑出两个结果）
    fig2E  只认黑色墨迹 + snake(win12)
    fig3A  颜色 DP + snake(win10)                        -> cover 1.0000
    fig3B/3C/3E  关掉厚度惩罚 + snake(win6, target0.30)   -> cover 1.0000，折角≈0
    fig3D  λ=0.08 + snake(win12, target0.5)               -> 折角 7.1 -> 0.14 px
    fig3F  大窗口(150 px)颜色重吸附，不做光滑              -> 跟随密集尖峰

八、已知的信息极限（不是算法缺陷）
  · fig3A/fig3D 在 x≈0 与交叉处，相邻曲线间距 ≤1 px 而线宽 9 px —— 墨迹饱和，
    单列剖面上只有 2 个墨峰，"谁在哪"在图像里不存在答案
  · fig3F 右侧同一列内曲线折返，任何 y(x) 单值曲线都无法同时覆盖两个分支
  · fig2E 起跳拐点处灰色单次记录压住黑线，遮挡处无法分辨
  这些位置的真实漏检段都在 qa/linegap_*.png 里标红，可逐段核对。

A. 本轮新增的四条严格判据（都能自己跑）
   check_kinks     折角 = |二阶差分|。跳线/粘连/沿圆环走的直接证据
   check_bias2     逐列"曲线行 − 墨迹亚像素中心"，并出 qa/bias_<tag>.png
   check_flip      只统计**分离区**（|Δy| > 3 倍线宽）里的顺序翻转次数
                   —— 真实交叉每对只翻 1 次；跳线会在几列内来回翻很多次
   check_profile   剖面失配：把各曲线按实测笔画剖面叠成预测剖面，与真实墨迹比形状。
                   并带**对照**（整体平移 ±1/±2 px）—— 判据有没有分辨力一目了然
   render_check    生成"诚实核对图" qa/<tag>_check.png：
                   1 px 中心线 + 按偏离着色（绿<=0.5px 黄<=1.5px 红>1.5px 灰=被遮挡）
                   为什么需要它：笔画宽 9~13 px，画 3 px 的粗叠加线时两侧必然露出原色，
                   看起来像"没重合"，其实中心线是重合的。

B. 用这四条判据逐项验证的结果（结论：已到可测极限）
   ① 顺序翻转（check_flip）
        fig2E 0 | fig3B 0 | fig3A 16(每对仅 1 次) | fig3C 2 | fig3D 29(每对≤2 次)
        fig3E 1 | fig3F 69（这一对在原图里本来就反复交叉）
      -> 分离区里**没有任何"来回翻"的跳线**。每对 1 次的翻转是曲线真实交叉。
   ② 剖面失配（check_profile）
        fig3A 0.0263，平移 1px -> 0.0286、2px -> 0.0348  => 判据有分辨力，
        当前结果优于"整体平移 1 px"，说明位置精度好于 1 px。
        fig3D 0.0403，平移 1px -> 0.0409、2px -> 0.0438（弱分辨力：十条线重叠时
        剖面形状对 1 px 平移本就不敏感 —— 这也是"合并带无法再提升"的直接证据）。
   ③ 折角（check_kinks）
        fig3D 10 条曲线 >1px 的折角 **0 处**（最大 0.39 px）
        fig3E **0 处**；fig3B 32、fig3C 30、fig3A 46 处（多为 1~2 px 级别）
   ④ 逐列偏差（check_bias2）中位 0.03~0.64 px，最大偏差出现在 x≈0 合并带。

C. 这一轮试过但对本任务**无效**的做法（已实测否决，写下来免得重复）
   · 法线方向亚像素重估（refine_normal.m，已保留为可选开关 normal=1）
     理论更严谨（竖直截面在弯折处有偏置），但实测中位偏差 0.05 -> 0.05 px，
     没有可测收益；对 fig3A 反而略降（1.0000 -> 0.9994）。默认关闭。
   · 自适应二值化 imbinarize(...,'adaptive')
     本类图是"白底 + 细暗线"，局部窗口里几乎全是白，阈值自适应后
     前景从 216442 px 暴涨到 2085976 px（过分割 10 倍），完全不可用。
   · 固定阈值放宽（fig2E inkMax 0.55 -> 0.62/0.70/0.80）
     会把灰色单次记录一起吃进来，覆盖率 0.968 -> 0.953/0.944/0.928，折角也变多。
   · 把光滑先验的目标调更紧（0.30 -> 0.15/0.06）
     折角反而变多（fig3B 32 -> 458 -> 904）：目标太紧时 λ 被迫变小，曲线开始跟噪声走。
   · 一阶斜率惩罚加大（fig3D λ 0.02 -> 0.08 -> 0.25）
     0.08 有小幅收益；0.25 时覆盖率崩到 0.941。真正的解是二阶（曲率）惩罚。

D. 关于"有没有用满 Image Processing Toolbox"
   已用：bwdist / bwmorph / imerode / imdilate / imclose / bwlabel / regionprops /
         strel / imresize / imfinfo / imfindcircles + interp2（法线采样）
   评估后**不适用**：imbinarize(adaptive)（见上）。
   本任务的瓶颈不是形态学算子，而是"同色系多线在饱和带里的归属" ——
   那里图像信息本身不足（相邻线间距 ≤1 px 而线宽 9 px），换任何算子都一样。
